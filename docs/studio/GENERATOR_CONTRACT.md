# The generator contract

For a `scripts/make_<kind>.py` script to be usable from `make_figure()`,
and, more strictly, to be `status="stable"` and shown in the Studio, it
must expose:

```python
DEMO_DATA: list[dict[str, Any]]

def make_<kind>(
    data: list[dict[str, Any]] | None = None,
    *,
    out: Path | str | None = None,
    title: str = "...",
    ...,
) -> Path:
    ...
```

`data=None` must fall back to `DEMO_DATA`. `out=None` must fall back to the
script's own default (historically `assets/svg-examples/<kind>.svg`, though
the Studio always passes an explicit `out` inside an isolated project
directory (see [ARCHITECTURE.md](ARCHITECTURE.md)) and never relies on
that fallback). The function must return the absolute `Path` it actually
wrote, and that path must exist.

## How a kind name resolves to a script

`sprezzature_figures.catalog` is the registry (`figures.json`, generated by
`tools/build_figures_catalog.py`) that maps a canonical kind name (which
may contain hyphens, e.g. `"connected-scatter"`) to a module path and
callable name, resolved independent of any naming convention. This is a
deliberate fix for a real bug: the dispatcher used to guess
`scripts/make_<kind.replace("-", "_")>.py`, which is wrong for exactly the
17 scripts whose filenames keep their hyphens
(`make_connected-scatter.py`, `make_liquid-gauge.py`, ...). `list_kinds()`,
`get_figure_definition()`, and alias resolution (`connected_scatter`,
`connected scatter`, and `connected-scatter` all resolve to the same
canonical kind) all go through the registry now, not string manipulation.

A script that exists on disk but isn't yet in `figures.json` still works
through a **deprecated fallback** (the old guess-the-filename logic),
emitting a `DeprecationWarning`; this exists so nothing already working
broke when the registry was introduced, but the Studio GUI must never rely
on it; only `status="stable"` kinds from the registry are shown there.

## Status levels

| Status | Meaning |
|---|---|
| `unavailable` | the script fails to import (missing dependency, syntax error) |
| `legacy` | imports fine, but is missing `DEMO_DATA` and/or `make_<kind>()` |
| `experimental` | contract-complete, but the last `--render` audit didn't confirm it renders (or wasn't run) |
| `stable` | contract-complete **and** confirmed to render by the last audit run |

Run `python tools/audit_generators.py --render` to regenerate
`docs/studio/generator_audit.json`/`GENERATOR_AUDIT.md`, then
`python tools/build_figures_catalog.py` to regenerate the registry from it
(cross-referenced against `FIGURES.md`'s category/description text).
`tools/build_figures_catalog.py`'s `HAND_ROLES` dict is where
`required_roles`/`optional_roles` are hand-declared for stable figures:
regenerating the catalogue re-applies these, so they survive a rebuild.

## Adding a new stable figure

1. Write `scripts/make_<kind>.py` following the contract above (copy the
   pattern of an existing hand-authored-SVG generator, e.g. `make_bar.py`
   or `make_waffle.py`). House policy: hand-authored SVG only, no Vega and
   no matplotlib.
2. Add a row to `FIGURES.md` (kind, category, one-line "when to use").
3. Add a `HAND_ROLES` entry in `tools/build_figures_catalog.py` naming the
   figure's required/optional data roles, **using the exact field names
   your `DEMO_DATA` rows use**, so the Studio's role-binding UI can hand it
   `make_figure()`-ready rows with no per-kind glue code.
4. Run `python tools/audit_generators.py --render` then
   `python tools/build_figures_catalog.py`.
5. Confirm it: `make-figure <kind> --out check.svg` (or `.png`), and
   look at the output; an audit `status="stable"` only means the file was
   non-empty, not that it looks right.
